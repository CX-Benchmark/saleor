## system

**What it is.** Saleor 3.24.0-a.0 (`pyproject.toml` `version`): a headless, API-only e-commerce backend ("GraphQL native, API-only platform", `README.md`). Python 3.12, Django ~5.2, graphene <3 on graphql-core-legacy 2, Celery, Postgres (primary plus optional replica, `saleor/settings.py` `DATABASES`, `PrimaryReplicaRouter`), Redis/Valkey cache (`CACHES` from `CACHE_URL`/`REDIS_URL`), optional S3/GCS/Azure media storage (`STORAGES`). Dashboard and storefront are separate repositories (README); out of view.

**Processes.**
- Web: `uvicorn saleor.asgi:application --host=0.0.0.0 --port=8000 --workers=2 --ws=none --no-server-header --limit-max-requests=10000` (`Dockerfile` `CMD`). ASGI wrappers (`saleor/asgi/__init__.py`): `health_check(.., "/health/")`, `gzip_compression`, `cors_handler`, `telemetry_middleware`, and `usage_telemetry_middleware` when `SEND_USAGE_TELEMETRY` (default True; sends instance id, version, object counts via `HTTPClient`, `saleor/asgi/usage_telemetry.py`). Django `MIDDLEWARE` is only `SecurityMiddleware`, `CommonMiddleware`, `saleor.core.middleware.jwt_refresh_token_middleware` (`settings.py`): no session, CSRF or authentication middleware. Authentication happens per GraphQL request in `saleor/graphql/context.py` `get_context_value`.
- Workers/scheduler: `celery --app saleor.celeryconf:app worker -E`; `celery ... beat --scheduler saleor.schedulers.schedulers.DatabaseScheduler` (`pyproject.toml` `[tool.poe.tasks]`); periodic jobs in `settings.py` `CELERY_BEAT_SCHEDULE`. Without `CELERY_BROKER_URL` tasks run inline (`CELERY_TASK_ALWAYS_EAGER = not CELERY_BROKER_URL`).
- Operator CLI: `manage.py` commands in `saleor/*/management/commands/` (`createsuperuser`, `changepassword`, `create_app`, `install_app`, `populatedb`, `cleardb`, `clearorders`, ...).

**HTTP routes** (`saleor/urls.py`): `^graphql/$` (`csrf_exempt(GraphQLView)`), `^plugins/channel/<channel_slug>/<plugin_id>/`, `^plugins/global/<plugin_id>/`, `^plugins/<plugin_id>/`, `^thumbnail/<instance_id>/<size>/[<format>/]`, `^image/<instance_id>/$`, `^.well-known/jwks.json$`. Only when `DEBUG`: `/media/...` (`serve_media_view`), `^static/`, `^$` (`home`). `/health/` is answered by the ASGI wrapper before Django.

**Components (under `saleor/`).**
- `graphql/`: the single public API; `Query`/`Mutation` composed in `saleor/graphql/api.py` from `saleor/graphql/*/schema.py`; storefront (anonymous/customer), dashboard (staff) and apps share it.
- `account/`, `auth/`, `permission/`, `core/jwt*.py`, `core/auth_backend.py`: users, staff, permission groups, JWT, login throttling (`account/throttling.py`).
- `app/`, `webhook/`: third-party Apps (tokens, permissions, manifests, extensions); outbound async/sync webhooks (`webhook/transport/`), sync-response schemas (`webhook/response_schemas/`), circuit breaker.
- `checkout/`, `order/`, `payment/` (transaction API, legacy payments, `payment/gateways/stripe`), `giftcard/`, `discount/`, `tax/`, `shipping/`, `warehouse/`: money and stock flows.
- `plugins/`: plugin manager and built-ins (`settings.py` `BUILTIN_PLUGINS`: `DeprecatedAvataxPlugin`, `WebhookPlugin`, `StripeGatewayPlugin`, `UserEmailPlugin`, `AdminEmailPlugin`, `OpenIDConnectPlugin`); inbound `/plugins/...` (`plugins/views.py`).
- `thumbnail/`: `/thumbnail/` and `/image/`; `core/views.py`: jwks, DEBUG media/home.
- `csv/` exports, `invoice/`, `product/`, `attribute/`, `channel/`, `menu/`, `page/`, `site/`, `seo/`, `translations/`, `schedulers/`.

**Principals it trusts.**
- Staff: `User.is_staff` plus permissions from groups and `user_permissions` (`JSONWebTokenBackend._get_permissions`, read from the replica). Superusers pass `ensure_can_manage_permissions` and `can_user_manage_group_channels`.
- Apps: bearer tokens and `App.permissions` (`saleor/graphql/app/dataloaders/app.py` `AppByTokenLoader`).
- Customers (self-registered) and anonymous callers.
- Plugins: Python classes in `BUILTIN_PLUGINS` plus every installed package exposing entry-point group `saleor.plugins`, appended to `INSTALLED_APPS`/`PLUGINS` at settings load (`settings.py` "Plugin discovery"); they run in-process with no sandbox.
- External services configured by staff: Stripe, an OIDC IdP, Avatax, SMTP, AWS SQS / Google Pub/Sub, oEmbed providers.

**Build, ship, deploy.**
- `Dockerfile`: build stage `python:3.12` with `uv sync --locked`; final `python:3.12-slim`; `COPY . /app` (`.dockerignore` drops dotfiles, `media`, `static`, `node_modules`); `collectstatic` run with `SECRET_KEY=dummy`; `EXPOSE 8000`. A `saleor` user is created and owns `/app`, but there is no `USER` directive, so the process runs as root unless the runtime overrides it. `DEBUG` is not set in the image.
- CI publishes multi-arch images to `ghcr.io/<owner>/<repo>` through `.github/workflows/publish-containers.yml`, which calls `saleor/saleor-internal-actions/.github/workflows/build-push-image-multi-platform.yaml` (out of view): `unstable-` tags on every push to `main` or `ci/**` (`publish-main.yml`), release tags from `create-tag-with-release-pr.yml` / `dispatch-release-pr-manually.yml`, load-test images from labelled PRs (`publish-load-test.yml`).
- `deployment/elasticbeanstalk/Dockerrun.aws.json` runs `saleor/saleor:latest` on container port 8000.
- AGENTS.md says Saleor "is deployed for horizontal scale-out: many identical Kubernetes pods (web + Celery workers) run concurrently behind a load balancer, against a shared Postgres (with read replicas) and shared Redis/broker", and that "a deployment may serve several sites from one process". `settings.py` sets `SITE_ID = 1` unconditionally; multi-site therefore depends on an overriding settings module, which is out of view.
- SECURITY.md: supported versions are 3.22 and later. README: "The `main` branch is the development version of Saleor and it may be unstable."

## adversaries

**How access is decided (applies to every GraphQL entry point below).**
- Requestor: `get_user_or_app_from_context` returns `context.app or context.user` (`saleor/graphql/utils/__init__.py`).
- App auth: token from header `Authorization-Bearer` or `Authorization: Bearer|JWT <token>` (`saleor/core/auth.py` `get_token_from_request`); treated as an app token only if exactly 30 characters (`promise_app`, `saleor/graphql/app/dataloaders/utils.py`); candidates found by `token_last_4`, verified with Django `check_password` against the hashed `AppToken.auth_token`, a positive match cached 30 days under an md5-of-token key; app must be `is_active` and not removed (`AppByTokenLoader.batch_load`). Only set when `request.path == API_PATH` (`set_app_on_context`).
- User auth (`saleor/core/auth_backend.py` `load_user_from_request`): token must claim `owner == "saleor"` (unverified pre-check `is_saleor_token`), then `jwt_decode`; type `access` or `thirdparty`; active user looked up by `email`; `token` claim must equal `user.jwt_token_key`. For `access` tokens `SiteSettings.password_login_mode` CUSTOMERS_ONLY strips staff and permissions, DISABLED rejects. A `permissions` claim replaces effective permissions; an `is_staff: true` claim sets staff. If that backend returns nothing, `PluginBackend` calls each plugin's `authenticate_user` (OIDC below).
- Mutations: `BaseMutation.mutate` calls `check_permissions`, which returns True when `Meta.permissions` is empty (`saleor/graphql/core/mutations.py`). This is the application-wide default: a mutation without `Meta.permissions` is open unless it overrides `check_permissions`/`mutate` or checks inside `perform_mutation`. With permissions, `one_of_permissions_or_auth_filter_required` (`saleor/permission/utils.py`) passes on any one listed permission or any listed authorization filter (`saleor/permission/auth_filters.py`: `AUTHENTICATED_APP`, `AUTHENTICATED_USER` = active user, `AUTHENTICATED_STAFF_USER`; `OWNER` has no function and never passes by itself).
- Query fields: `PermissionsField` wraps the resolver in `one_of_permissions_required` (`saleor/graphql/core/fields.py`, `saleor/graphql/decorators.py`); other fields check in their resolver or not at all. `permission_required` refuses `MANAGE_STAFF` to apps.
- Storefront gate: when `Shop.allowStorefrontTraffic` is false, `is_storefront_traffic_blocked` (`saleor/graphql/storefront_traffic.py`) returns HTTP 401 for every request that is neither an app nor staff; it runs in `GraphQLView.execute_graphql_request` after parsing, validation and the cost check, and the flag is cached 5 minutes per site (ADR-0006/0007).

**A1. Anonymous internet client** (storefront visitor, bot). Reaches, with no credential:
- `POST /graphql/`: bodies `application/json` (orjson), `application/graphql`, urlencoded, or `multipart/form-data` with `operations`/`map` (`GraphQLView.parse_body`, `get_graphql_params`, `obj_set`). Batches capped by `GRAPHQL_BATCH_MAX_COUNT` (default 1). Subscription operations rejected. `GET /graphql/` renders `templates/graphql/playground.html` when `PLAYGROUND_ENABLED` (default True).
- Anonymous, handler read: `checkoutCreateFromOrder` (any `Order` global ID; copies its lines into a new checkout), `deliveryOptionsCalculate` (checkout ID; triggers sync shipping webhooks), `tokenCreate` (throttled, below).
- No `Meta.permissions`; handler searched for permission checks, not read whole (access beyond the noted checks not verified): `checkoutCreate`, `checkoutLinesAdd`/`LinesUpdate`/`LinesDelete`, `checkoutEmailUpdate`, `checkoutAddPromoCode`/`RemovePromoCode` (vouchers and gift-card codes), `checkoutShippingAddressUpdate`, `checkoutBillingAddressUpdate`, `checkoutDeliveryMethodUpdate`, `checkoutShippingMethodUpdate`, `checkoutCustomerNoteUpdate`, `checkoutLanguageCodeUpdate`, `checkoutPaymentCreate`, `checkoutComplete` (acts for `checkout.user` when the requestor has `IMPERSONATE_USER`). They load the checkout through `get_checkout` (`saleor/graphql/checkout/mutations/utils.py`, read), which has no owner check; custom line prices need an app with `HANDLE_CHECKOUTS` (`check_permissions_for_custom_prices`); private metadata on create needs extra permissions. Also `transactionInitialize` (overriding `action` needs an app with `HANDLE_PAYMENTS`), `transactionProcess`, `paymentGatewayInitialize`, `paymentInitialize`, `paymentCheckBalance`, `accountRegister`, `requestPasswordReset`, `setPassword`, `confirmAccount`, `appTokenVerify`, `tokenRefresh`, `tokenVerify`, and `externalAuthenticationUrl`/`ObtainAccessTokens`/`Refresh`/`Logout`/`Verify` (they delegate to plugin methods; the OIDC ones were read).
- Mutations with no `Meta.permissions` that check in the handler: `attributeCreate` (`check_attribute_type_permissions` in `perform_mutation`; the other `attribute*`/`attributeValue*` mutations share the mixin, not verified each); `externalNotificationTrigger` (per-model permission from `validate_and_get_payload_params`); `updateMetadata`/`deleteMetadata`/`updatePrivateMetadata`/`deletePrivateMetadata` (`BaseMetadataMutation.mutate`, `saleor/graphql/meta/mutations/base.py`: permission per type from `PUBLIC_META_PERMISSION_MAP`/`PRIVATE_META_PERMISSION_MAP` in `saleor/graphql/meta/permissions.py`; public metadata of `Checkout`/`CheckoutLine` maps to `no_permissions`; objects also resolvable by raw order UUID or checkout token, `get_instance_by_token`); `accountAddressUpdate`/`accountAddressDelete` (`check_can_edit_address`: MANAGE_USERS or owning user, not apps without it); `channelUpdate` (overridden `check_permissions`: MANAGE_CHANNELS or the per-setting permissions).
- Anonymous queries (no `PermissionsField` permissions; resolvers apply visibility): `shop`, `products`/`product`, `productVariants`/`productVariant`, `categories`/`category`, `collections`/`collection`, `productTypes`/`productType`, `pages`/`page`, `pageTypes`/`pageType`, `menus`/`menu`, `menuItems`/`menuItem`, `attributes`/`attribute`, `channel`, `checkout` (`resolve_checkout`: any checkout of an active channel by id/token; inactive channel needs MANAGE_CHECKOUTS, IMPERSONATE_USER or HANDLE_PAYMENTS), `order` (`resolve_order` by UUID with no permission check; `externalReference` path needs MANAGE_ORDERS), `orderByToken`, `me`, `addressValidationRules`, `taxTypes`, `refundSettings`, `returnSettings` (`permissions=[]`), `webhookSamplePayload` (resolver requires the event's permission when one is defined, `saleor/graphql/webhook/resolvers.py`), `_entities` (max `FEDERATED_QUERY_MAX_ENTITIES`; per-type `__resolve_references`: `User` scoped by `resolve_users`, `Order` by `resolve_orders`; other types not verified), `_service`.
- Bearer capabilities an anonymous caller can hold or guess: checkout ID/token (UUID); order ID (UUID). For orders with `use_old_id=False`, `Order.resolve_billing_address`, `resolve_shipping_address` and `resolve_user_email` (`saleor/graphql/order/types.py`) return unobfuscated values to any caller; orders with `use_old_id=True` are also addressable by sequential `number` (`resolve_order`, `BaseMutation._get_node_by_pk`) and get obfuscated PII unless owner or MANAGE_ORDERS. Transaction token (ADR-0010: "a capability accepted by the unauthenticated transactionInitialize/transactionProcess mutations"). Gift card codes (ADR-0001, bearer). Password-reset/confirmation tokens (`TOKEN_GENERATOR_CLASS` = Django `PasswordResetTokenGenerator`). OIDC `state` (Django `signing`).
- `/plugins/...` (`saleor/plugins/views.py` -> `PluginsManager.webhook` / `webhook_endpoint_without_channel`): no authentication in front; dispatched to the plugin's `webhook()`. Among built-ins only `StripeGatewayPlugin.webhook` implements it: requires a channel, path `/webhooks/`, and `handle_webhook` (`saleor/payment/gateways/stripe/webhooks.py`) verifies `stripe-signature` with `stripe.Webhook.construct_event` against the channel's `webhook_secret_key` (HTTP 500 if unset). Handlers of external plugins are out of view.
- `/thumbnail/`, `/image/` (`saleor/thumbnail/views.py`): anonymous; accept global IDs of `User` (avatar, by UUID), `Category`, `Collection`, `ProductMedia`, `App`, `AppInstallation`; no publication or channel check on the instance; on a miss they decode the stored image with Pillow, save a `Thumbnail` (writer DB) and emit `thumbnail_created`, then redirect to the storage URL.
- `/.well-known/jwks.json` (public key), `/health/` (empty 200).
- Login throttling: `tokenCreate` uses `authenticate_with_throttling` (`saleor/account/throttling.py`) keyed on `get_client_ip`, which returns the first valid IP in `X-Forwarded-For` before `REMOTE_ADDR` (`saleor/core/utils/__init__.py`). `REAL_IP_ENVIRON` is defined in `settings.py` and referenced nowhere else in `saleor/` (grep). The same IP is sent as customer IP to payment gateways (`graphql/payment/mutations/transaction/utils.py`, `checkout_payment_create.py`).
- Cost and size limits: `validate_query` (`saleor/graphql/core/validators/__init__.py`) runs the cost validator (`GRAPHQL_QUERY_MAX_COMPLEXITY` 50000, `query_cost_map.py`), `AliasCountLimitRule` (100) and `MutationCountLimitRule` (4); `GraphQLView` rejects on their errors only `if settings.GRAPHQL_QUERY_MAX_COMPLEXITY and cost_errors`, so complexity 0 also disables the alias and mutation-count limits. Pagination capped at 100 (`GRAPHQL_PAGINATION_LIMIT`). `settings.py` does not override `DATA_UPLOAD_MAX_MEMORY_SIZE` (Django default); oversize bodies get 413 in `_handle_query`.
- Through a victim's browser: `cors_handler` reflects any `Origin` matching `ALLOWED_GRAPHQL_ORIGINS` (fnmatch, default `*`) and always sends `Access-Control-Allow-Credentials: true`. The refresh token is also set as cookie `refreshToken` (HttpOnly; `Secure` and `SameSite=None` when not DEBUG, `Lax` in DEBUG) by `jwt_refresh_token_middleware`; `tokenRefresh` reading the cookie requires a `csrfToken` matching the one inside the refresh JWT (`RefreshToken.clean_csrf_token`). Access tokens travel only in headers.

**A2. Authenticated customer** (self-registered via `accountRegister`). Adds the `AUTHENTICATED_USER` mutations: `accountUpdate`, `accountAddressCreate`, `accountSetDefaultAddress`, `accountRequestDeletion`, `accountDelete`, `passwordChange`, `requestEmailChange`, `confirmEmailChange`, `sendConfirmationEmail`, `tokensDeactivateAll`, `checkoutCustomerAttach`/`Detach` (also apps), `storedPaymentMethodRequestDelete`, `paymentGatewayInitializeTokenization`, `paymentMethodInitializeTokenization`, `paymentMethodProcessTokenization` (handlers not read). Owner checks read: `check_can_edit_address`; `public_user_permissions`/`public_address_permissions` (own objects need no permission); `resolve_users` returns only the requestor without MANAGE_USERS/MANAGE_STAFF; `Order.__resolve_references` via `resolve_orders`. Isolation of other customers' checkouts and orders rests on the UUIDs above.

**A3. Staff user with partial permissions, or in a channel-restricted group.** Reaches the privileged mutations and `PermissionsField` queries for the permissions held, plus `AUTHENTICATED_STAFF_USER` ones (`webhookDryRun`, `webhookTrigger`, `fileUpload`, `userAvatarUpdate`/`Delete`, tax and channel/app listing queries). Escalation guards read: `can_user_manage_group` (group permissions within the user's and group channels within the user's accessible channels) and the `get_not_manageable_permissions*` helpers (`saleor/graphql/account/utils.py`); `ensure_can_manage_permissions` (requestor must hold every permission given to an app; superuser exempt) and `ensure_app_permissions_allowed` (MANAGE_APPS never grantable to an app) in `appCreate`/`appUpdate`/`appInstall` (`saleor/graphql/app/utils.py`; manifest variant in `saleor/app/manifest_validations.py`); `can_manage_app`. Channel restriction (`Group.restricted_access_to_channels`, `saleor/account/models.py`) is enforced by `BaseMutation.check_channel_permissions`, called from order, draft-order, fulfillment, invoice, legacy payment and transaction-action mutations (grep); apps bypass it ("App has access to all channels"). MANAGE_PLUGINS edits plugin configuration, including Handlebars email templates (`EmailTemplate`, `saleor/plugins/models.py`) and gateway/IdP secrets. MANAGE_APPS installs apps from any manifest URL.

**A4. Third-party App or stolen app token.** Acts with its own permissions across all channels. Can:
- register webhooks (MANAGE_APPS or AUTHENTICATED_APP) whose `target_url` scheme is `http`, `https`, `awssqs` or `gcpubsub` (`WebhookURLField`/`AppURLValidator`, `saleor/webhook/models.py`) and whose subscription queries are resolved with `request.app = app` (`initialize_request`, `saleor/graphql/webhook/subscription_payload.py`); ADR-0008 says `identifier` addresses only the calling app's own webhooks;
- answer sync webhooks (payment gateway/transaction sessions, checkout/order taxes, shipping lists and filters, stored payment methods) parsed by pydantic models in `saleor/webhook/response_schemas/`, feeding prices, taxes and transaction state;
- report payment state: `transactionCreate`/`transactionUpdate`/`transactionEventReport` (HANDLE_PAYMENTS; update and report also require `check_if_requestor_has_access` on the transaction); `orderCreateFromCheckout` (HANDLE_CHECKOUTS);
- `appSelfUpdate`, `appProblemCreate` (AUTHENTICATED_APP);
- receive staff-scoped tokens: app extensions (dashboard iframes, README) get `thirdparty` JWTs carrying app ∩ user permissions (`create_access_token_for_app`, `create_access_token_for_app_extension`, `saleor/core/jwt.py`);
- subscribe to the `OBSERVABILITY` event (its permission is `MANAGE_OBSERVABILITY` in `WebhookEventAsyncType`, `saleor/webhook/event_types.py`), which, when `OBSERVABILITY_BROKER_URL` is set, carries reports of API calls and webhook deliveries; headers and fields listed in `saleor/webhook/observability/sensitive_data.py` are hidden by `obfuscation.py` (not read in detail).
Outbound delivery: HTTP via `HTTPClient` (`saleor/core/http_client.py`, requests_hardened: IP filter on by default, loopback refused unless `HTTP_IP_FILTER_ALLOW_LOOPBACK_IPS`, `never_redirect=True`, timeout 2 s connect / 18 s); SQS via boto3 with credentials from the URL userinfo, or the pod's ambient AWS credentials when absent (`get_boto3_sqs_client`); Pub/Sub via `pubsub_v1.PublisherClient()` with ambient GCP credentials (`get_google_pubsub_client_and_retry_config`). Payload signature: HMAC-SHA256 with the webhook `secret_key` if set, else detached RS256 JWS (`signature_for_payload`, `saleor/webhook/transport/__init__.py`). Install flow fetches the manifest, brand logo and posts the token to `tokenTargetUrl` via `HTTPClient` (`saleor/app/installation_utils.py`).

**A5. Malicious external peer or provider.** Stripe webhook senders (signature above). OIDC IdP (`saleor/plugins/openid_connect/`): id tokens and JWT-shaped access tokens are decoded with keys from the configured JWKS URL (fetched with `HTTPClient`; `get_parsed_id_token`, `decode_access_token`; claim checks inside `get_decoded_token` not read); opaque access tokens are validated by calling the configured userinfo URL (`get_user_info_from_cache_or_fetch`); users created or updated from claims (`get_or_create_user_from_payload`); staff granted when the email domain is in `staff_user_domains`, or from `saleor:` scopes when `use_oauth_scope_permissions`; token-endpoint calls go through authlib `OAuth2Client`, not `HTTPClient`. Avatax (`plugins/avatax`). oEmbed providers via `micawber.bootstrap_basic()` (`saleor/core/utils/validators.py`, not `HTTPClient`). Remote product-media URLs fetched with `HTTPClient` (`saleor/graphql/product/utils.py`, `saleor/product/tasks.py`).

**A6. Malicious file.** Upload paths: `fileUpload` (app or staff), product/category/collection images (MANAGE_PRODUCTS), staff avatars, fetched app logos. `saleor/graphql/core/validators/file.py`: `validate_upload_file` (python-magic on the first 2048 bytes, `ALLOWED_MIME_TYPES` allowlist extendable by env `UPLOAD_ADDITIONAL_ALLOWED_MIME_TYPES`, extension must match) and `clean_image_file` (`MAX_IMAGE_FILE_SIZE` 10 MB, pixel cap, EXIF). Pillow's global limit is set in `CoreAppConfig.ready` to `MAX_IMAGE_PIXELS // 2`. Stored images are decoded again by the anonymous `/thumbnail/`.

**A7. Plugin author.** Anything published under the `saleor.plugins` entry-point group and installed in the image is imported as trusted code. App authors are A4.

**A8. Operator or local user.** Management commands and environment variables; no remote reach.

**Entry points left out.** `saleor/graphql/schema.graphql` has 334 Mutation and 89 Query fields. About 250 mutations and about 40 queries that require a specific Saleor permission are not listed one by one; they are registered in the `*Mutations`/`*Queries` classes of `saleor/graphql/*/schema.py`, composed in `saleor/graphql/api.py`. Celery tasks (autodiscovered in `saleor/celeryconf.py`) consume only broker messages.

## assets

**Priorities** (kept from the threat model on file):
1. Payment integrity: prices, totals, discounts and vouchers, gift-card balances (ADR-0004: atomic, self-clamping adjustments), transaction/refund state, order creation without payment.
2. Authorization state: staff permissions and groups, channel-scoped access, app permissions and tokens, customer data isolation by global ID, privilege escalation through groups or apps.
3. Customer PII and secrets.
4. Server integrity: SSRF via webhook targets, manifests and image URLs; injection; template/email rendering; file handling.
5. Availability: GraphQL cost, shared Postgres (AGENTS.md: "the scaling bottleneck").

**Credentials and where they come from** (all from environment in `saleor/settings.py` unless noted):
- `RSA_PRIVATE_KEY` (+ `RSA_PRIVATE_PASSWORD`): signs every JWT (RS256) and webhook JWS (`saleor/core/jwt_manager.py` `JWTManager`). Unset with DEBUG: a key is generated and written to `<PROJECT_ROOT>/.jwt_key.pem`. Unset without DEBUG: `ImproperlyConfigured` (`get_private_key`, `validate_configuration` called from `saleor/core/apps.py`).
- `SECRET_KEY`: Django signing (OIDC `state`), password-reset and confirmation tokens, and HS256 JWTs: `JWTManager.decode` verifies with `SECRET_KEY`/HS256 whenever the token header `alg` is not RS256. Random per process when unset under DEBUG; no fallback otherwise.
- `DATABASE_URL`/`DATABASE_URL_REPLICA`, `CACHE_URL`/`REDIS_URL`, `CELERY_BROKER_URL`, `EMAIL_URL`, `USER_EMAIL_URL`, `SENDGRID_*`, `AWS_*`, `GS_*`/`GOOGLE_APPLICATION_CREDENTIALS`, `AZURE_*`, `SENTRY_DSN`, `OBSERVABILITY_BROKER_URL`.
- App tokens: Django-hashed `AppToken.auth_token` plus `token_last_4` (`saleor/app/models.py`); successful lookups cached in the shared cache for 30 days.
- Webhook `secret_key` (`Webhook.secret_key` CharField) and SQS credentials embedded in `target_url`.
- Plugin configuration secrets (Stripe `secret_api_key`/`webhook_secret_key`, OIDC `client_secret`, SMTP passwords) in `PluginConfiguration` JSON in the database; typed `SECRET`/`PASSWORD`/`SECRET_MULTILINE` (`saleor/plugins/base_plugin.py`).
- User passwords: Django default hashers plus `BCryptPasswordHasher` and `SHA512Base64PBKDF2PasswordHasher` (`PASSWORD_HASHERS`); per-user `jwt_token_key` revokes all tokens.

**Data.**
- PII in `User`, `Address`, `Order` (`user_email`, addresses), `Checkout`, customer and order events. Sentry: `send_default_pii=False`, `EventScrubber` denylist adds `private_metadata` and name/email/address keys (`SENTRY_INIT`).
- `private_metadata` on most models; reads gated by `check_private_metadata_privilege` (`saleor/graphql/meta/resolvers.py`) using `PRIVATE_META_PERMISSION_MAP`.
- Files: default (public) storage holds CSV exports (`ExportFile.content_file`, URL returned by `build_absolute_uri(content_file.url)` in `saleor/graphql/csv/types.py`), invoices, product/category/collection images, avatars, app logos, thumbnails. Only webhook payload files (`EventPayload.payload_file`, `saleor/core/models.py`) use `private_storage` (`PRIVATE_FILE_STORAGE`). No query-string signing is configured by default (`AWS_QUERYSTRING_AUTH`, `GS_QUERYSTRING_AUTH` default False).
- Event payloads and delivery attempts kept `EVENT_PAYLOAD_DELETE_PERIOD` (14 days); CSV exports are built by Celery tasks in `saleor/csv/` (petl) and deleted after `EXPORT_FILES_TIMEDELTA`.

**Trust boundaries and where enforced.**
- Internet to web pod: `saleor/graphql/context.py` (auth), mutation/field permission checks above, `storefront_traffic.py`, `validate_query`; `/plugins/` delegates to each plugin; `/thumbnail/` and `/image/` have none.
- Saleor to app endpoints (outbound): `HTTPClient` IP filter and no redirects for HTTP(S); none for SQS/Pub/Sub, which use cloud APIs.
- App responses to Saleor (sync webhooks): pydantic schemas in `saleor/webhook/response_schemas/`; apps are semi-trusted.
- PSP/IdP to Saleor: Stripe signature (`handle_webhook`); OIDC tokens decoded with keys from the configured JWKS URL, or checked against the userinfo URL.
- Pods to Postgres/Redis/broker: trusted. The shared cache stores authorization inputs (app-token match cache, login-throttle counters, storefront flag, introspection responses); Celery accepts JSON only (`CELERY_ACCEPT_CONTENT = ["json"]`); permissions are read from the replica (`JSONWebTokenBackend._get_permissions`).
- Process to plugins: no boundary.
- Site to site: `Site.objects.get_current()`; storefront flag cache key namespaced by site (`_get_allow_storefront_traffic_cache_key`). AGENTS.md warns that keys or filters baked to a single site "lets one tenant read another's data".

## out-of-scope
What follows reports the repositories' own statements and exempts nothing from the audit.


- `SECURITY.md`: report privately (GitHub advisories or security@saleor.io); reports must be reproducible and self-contained; "We do not accept ... - `docs/adr/0001`: gift cards are bearer instruments; "whoever holds the code can spend it, including in guest checkout"; assignment is an opt-in restriction and its rejection "must be generic". `0002`: a restricted card stays restricted after its customer is deleted. `0003`: assignment is manual only.

## facts

- **Security policy:** `SECURITY.md` exists (private reporting, supported ≥ 3.22, no bounty).
- **Templates and escaping:** Django templates (`settings.py` `TEMPLATES`, `DjangoTemplates`, no `autoescape` option, so autoescape on); no `|safe` or `autoescape` in `templates/` (grep). Emails: pybars3 Handlebars compiled at send time (`saleor/plugins/email_common.py`); `{{ }}` escapes, helpers `format_address`/`price` return `pybars.strlist` (not escaped); no `{{{` in shipped default templates (grep); templates are staff-editable (`EmailTemplate`). Rendered HTML is parsed by `lxml.html.fromstring` in `email_common.py`. Rich text: EditorJS cleaned with nh3 (`saleor/core/editorjs/cleaners.py`, `saleor/core/cleaners/html.py`, `HTML_CLEANER_PREFS`).
- **Serialization:** request JSON via `orjson.loads` (`GraphQLView.parse_body`, multipart `operations`/`map`); responses via `orjson.dumps`; Celery task/result serializer JSON, `CELERY_ACCEPT_CONTENT = ["json"]`; Django `signing` (JSON) for OIDC state; pydantic for sync-webhook responses and complex inputs. No `pickle`, `yaml.load`, `marshal`, `eval`/`exec`, `subprocess` or `shell=True` in non-test code (grep). Raw SQL only for sequences/advisory locks (`order/models.py`, `discount/models.py`, `core/db/locks.py`) and `populatedb`.
- **Authentication and sessions:** no Django sessions. JWT RS256 (`JWTManager`) with HS256/`SECRET_KEY` accepted for non-RS256 headers; TTLs `JWT_TTL_ACCESS` 5 min, `JWT_TTL_APP_ACCESS` 5 min, `JWT_TTL_REFRESH` 30 days, email-change 1 h; types `access`, `refresh`, `thirdparty` (app/extension tokens carrying a `permissions` claim = app ∩ user permissions, `_create_access_token_for_third_party_actions`), `confirm-email-change`. Refresh cookie `refreshToken` plus CSRF token in the refresh JWT. `jwt_decode` defaults to `verify_aud=False` ("we decode our own tokens", `JWTManager.decode`), so tokens carrying an `aud` claim (app audiences, `custom:<audience>` from `tokenCreate`) still decode. App tokens: 30-char bearer. Login throttling per IP and per IP+user in the cache (`throttling.py`, delays doubling up to 3600 s). Password minimum length 8 (`AUTH_PASSWORD_VALIDATORS`). `PasswordLoginMode` site setting. OIDC plugin authenticates its own tokens and IdP access tokens (`OpenIDConnectPlugin.authenticate_user`).
